Mock MCP launch checklist

This is an operator-run test deployment, not an automatic connection. Connection status: Not verified. The site does not probe the server or accept a Bearer token.

  1. Update & test: Pull the reviewed GitHub main commit on the authorized server. Run PYTHONPATH=src python -m unittest discover -s tests -p 'test_mock_http_mcp.py' -v and check the results.
  2. Private test token: Generate a random token on the server with python -c 'import secrets; print(secrets.token_urlsafe(48))'. Store it in private service configuration, not in this webpage, GitHub or logs.
  3. Enable mock mode: Configure AGENTSTEERS_MCP_MOCK_ENABLED=1, AGENTSTEERS_MCP_MOCK_TOKEN, AGENTSTEERS_MCP_MOCK_HOST=mcp.agentsteers.com and AGENTSTEERS_MCP_MOCK_REPOS=scyllarusllc/agentsteers.
  4. Start separately: Under a dedicated non-root account, start the standalone WSGI app agentsteers.mock_http_mcp:application with Gunicorn on 127.0.0.1:8766, using one worker and the project src Python path.
  5. Expose HTTPS only after verification: Have Caddy forward the mcp.agentsteers.com/mcp route to that loopback service. Keep the normal website routes unchanged. Confirm TLS, Host and forwarded-protocol handling before changing the 503 prelaunch route.
  6. Test externally: Expect HTTP 401 without the token. With the token, verify MCP initialize, tools/list, and the four mock tools: submit_task, get_task_status, get_task_result, and cancel_task. No Codex commands should execute.

The planned endpoint is https://mcp.agentsteers.com/mcp. Public availability and ChatGPT Voice compatibility have not been confirmed. A successful website login does not authorize MCP access.

Rollback: Restore the MCP domain's Caddy 503 prelaunch configuration and stop the separate mock process. The website can remain online.
