THE GOAL: START IN 60 SECONDS

A voice-first bridge between ChatGPT on your iPad and Codex CLI on your own server. Guide coding work through conversation, with infrastructure and permissions under your control.

Explore on GitHub ↗See the concept ↓

60-second quick-start target, not a measured result: The development mock can be started locally, but a fresh installation, production authentication, and end-to-end iPad Voice → MCP → Codex execution have not yet been validated. Production use is not ready.

THE FLOW

From a conversation
to a controlled coding task.

The proposed flow connects voice instructions, scoped authorisation, and an isolated coding worker on infrastructure you control.

01 · TALKiPad / ChatGPT VoiceDescribe the development task naturally.
→
02 · AUTHORIZEAgentSteers MCPAuthenticate, check scopes and repository access.
→
03 · EXECUTEYour server / Codex CLIRun approved work and return sanitized results.

Architecture in development. ChatGPT Voice tool support, production OAuth, the Frappe/MCP bridge, and live Codex execution still require integration and validation.

RESEARCH ROADMAP

When should agents
work in parallel?

We plan to compare sequential agents, asynchronous task handling, and independent workers on reproducible software-engineering tasks. The research will measure completion time, reliability, cost, resource contention and conflicting edits to learn when parallel execution helps—and when it does not.

Research proposal, not a shipped multi-agent feature or validated performance result.
