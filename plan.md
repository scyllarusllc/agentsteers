## Mock MCP launch checklist (operator-run; not deployed by this commit)

**Prerequisites:** an authorized Linux host, DNS and a valid TLS certificate for `mcp.agentsteers.com`, a dedicated non-root service account, an up-to-date repository checkout and isolated Python environment with `gunicorn` installed. Keep the current website service unchanged. Do not put secrets in the repo, shell history, GitHub Actions logs or the MCP Connection webpage.

1. Update the server checkout to the reviewed `main` commit. As the non-root service user, run offline tests before enabling anything:

   ```sh
   PYTHONPATH=src python -m unittest discover -s tests -p 'test_mock_http_mcp.py' -v
   PYTHONPATH=src python -m unittest discover -s tests -p 'test_remote_mcp_guard.py' -v
   ```

   Record results; do not infer a pass from the presence of test files.

2. Generate a fresh random Bearer Token on the server (`python -c 'import secrets; print(secrets.token_urlsafe(48))'`) and place it in a private service environment/secret file readable only by the service owner. Never paste the actual token in a public page or a support conversation. Configure the service environment:

   ```text
   AGENTSTEERS_MCP_MOCK_ENABLED=1
   AGENTSTEERS_MCP_MOCK_TOKEN=<server-generated-secret>
   AGENTSTEERS_MCP_MOCK_HOST=mcp.agentsteers.com
   AGENTSTEERS_MCP_MOCK_REPOS=scyllarusllc/agentsteers
   ```

   The placeholders must be replaced in the private configuration; they are not a ready-to-run shell command.

3. Start the **separate** app as the dedicated non-root account, using that service environment and the correct repository checkout:

   ```sh
   PYTHONPATH=src gunicorn --bind 127.0.0.1:8766 --workers 1 \
     --access-logfile - agentsteers.mock_http_mcp:application
   ```

   Use exactly one worker for this in-memory proof of concept: multiple workers do **not** share task state, and process restarts lose all mock tasks. Keep the backend port bound to loopback only. Use a supervised service for reboot recovery; this foreground example is a smoke test, not a permanent production unit.

4. **Only after the tests pass and the local process is healthy**, replace the **separate MCP domain's** prelaunch 503 block with a reviewed Caddy configuration equivalent to:

   ```caddyfile
   mcp.agentsteers.com {
       encode zstd gzip
       handle /mcp {
           reverse_proxy 127.0.0.1:8766
       }
       respond 404
   }
   ```

   Preserve the original Host header and trusted HTTPS forwarding; ensure Gunicorn only trusts forwarded scheme headers from loopback. Validate the Caddy configuration before reload. Do not add a proxy rule to the main website domain or expose port 8766 publicly. Do not switch the route until the service configuration and tests are checked.

5. From an authorized test client, check that `POST https://mcp.agentsteers.com/mcp` returns **401 without a token**. With the Bearer token and `Accept: application/json, text/event-stream`, send an MCP JSON-RPC `initialize` request, then `tools/list`; expect four named tools: `submit_task`, `get_task_status`, `get_task_result`, `cancel_task`. Exercise one complete mock task lifecycle, including cancellation, and verify no Codex/shell/Git operation occurred. Avoid writing token-bearing commands to shell history.

6. Report the page status as **Not verified** until live endpoint and client compatibility have actually been tested. This static page does not measure connectivity or accept a token. Test ChatGPT plugin and Voice separately; bearer-token support in the intended ChatGPT client is not assumed. For real worker execution, replace the shared mock token with actor-scoped OAuth and authorization.

**Rollback:** restore `deploy/Caddyfile.prelaunch` (503) for the MCP hostname, validate and reload Caddy, then stop the dedicated Mock MCP process. This does not require taking the AgentSteers website offline.

## Makefile MCP + Caddy integration (2026-11-09)

MCP development now has dedicated Makefile commands; this does **not** change the running server or public Caddy automatically:

```sh
make pull
make install                  # once on the host, if needed
make mcp-mock-install         # once; installs Gunicorn in local venv
make mcp-mock-test            # protocol, auth and proxy configuration tests
# Configure private AGENTSTEERS_MCP_MOCK_* environment variables.
make mcp-mock-start           # foreground; loopback 127.0.0.1:8766
```

From another terminal on the same authorized host, while the mock server is listening:

```sh
make mcp-mock-proxy-preview                       # read-only preview
make mcp-mock-proxy-apply                         # tests + Caddy validation + interactive confirmation
```

`CADDY_CONFIG=/path/to/Caddyfile` may be supplied if the server's real Caddyfile is not `/etc/caddy/Caddyfile`. The apply command requires permission to read and modify the real Caddyfile, plus permission to reload Caddy, and only works when that file has exactly one recognizable `mcp.agentsteers.com` block (the current 503 prelaunch block or the known mock proxy block). It refuses unknown/imported layouts: review such configurations manually; do **not** overwrite the site's entire Caddyfile. It checks that the loopback backend is listening, validates the candidate configuration using Caddy, asks for `ENABLE MOCK MCP`, backs up the original file, changes only the MCP hostname block, reloads Caddy, and attempts restoration if reload fails. It does not start a permanent supervised service, make DNS changes, or verify a live public connection.

The mock proxy template is `deploy/Caddyfile.mock-mcp`; the Caddy integration helper is `scripts/mcp_mock_caddy.py`. Run the public 401/initialize/tools smoke tests described above after activation. Keep the MCP connection website status as **Not verified** until actual client checks succeed. Caddy activation is separate from website publishing, and server secrets must remain outside GitHub.

## One-command temporary MCP test session

After the repository is updated on the authorized host, from the project root:

```sh
make mcp
```

The new `make mcp` target invokes `scripts/run_mcp_mock_session.py`. It creates a local Python virtual environment if absent, installs Gunicorn if necessary, runs the three Mock MCP/auth/Caddy unit test modules, and generates/reuses a random Bearer token in `~/.config/agentsteers/mock-mcp.token` (mode 0600; never committed or displayed). It requires read/write access to the actual Caddyfile (default `/etc/caddy/Caddyfile`, override with `CADDY_CONFIG`) and permission to reload Caddy. It refuses to replace an unknown MCP hostname configuration or an already-active proxy. When the operator types `ENABLE MOCK MCP`, it launches a single Gunicorn mock-only worker on `127.0.0.1:8766`, checks readiness, validates the proposed Caddyfile, backs up the original, and enables `https://mcp.agentsteers.com/mcp` through the dedicated Caddy host. No Codex CLI or arbitrary command execution is enabled.

**Temporary, foreground mode:** keep the terminal running during the test. On Ctrl+C, the script attempts to restore the original Caddyfile and stops the Mock process. If it cannot restore, it warns and the operator must restore the backup manually. This is not an always-on systemd service, does not update DNS, and does not prove public accessibility or ChatGPT Voice compatibility. The operator should check HTTPS 401 without a token and complete initialize/tools/list/mock lifecycle with the token.

The `mcp-mock-*` granular commands remain available for debugging and future supervised deployment. Use `make pull` first if the server checkout is behind `main`; `make mcp` intentionally does not change Git history or website deployments.
